# 数据接入、清洗与存储设计

状态：工程设计，非已经部署的系统。范围：A股 / ETF，分钟级监测、历史日线；默认仅研究用途。所有调度以 Asia/Shanghai 和交易所日历为依据。

## 两条采集链路

```text
盘中：Provider → 限速 / 超时 / 断路 → 不可覆盖原始批次 → 标准化 / 校验
                                                     ↓
                                             最新行情物化视图 → API → 前端
                                                     ↓
                                             分钟历史 Parquet

日终 / 回补：股票池与日历 → 按证券 / 日期分块 → 原始批次 → 清洗 / 对账
                                                        ↓
                                                日线与因子版本库
                                                        ↓
                                                DuckDB 研究查询 → API
```

前端只读本机 API，不从浏览器直连行情网站。Provider 必须声明上游、覆盖市场、频率、时间戳精度、单位、历史窗口、分页上限、权限和退市覆盖。不把 SDK 名称误当上游名称。

## 数据源分工

| 数据集 | 首期接口候选 | 更新设计 | 回补 / 降级 |
|---|---|---|---|
| A股日线 | AKShare `stock_zh_a_hist`；授权后 Tushare `daily` | 17:30日终首轮，20:00复核，次交易日盘前检查 | 按年或接口行数切片；显式未复权；记录返回覆盖范围 |
| ETF日线 | AKShare `fund_etf_hist_em` | 与日终行情同批验证 | 单独适配器；不默认 Tushare 股票接口覆盖 ETF |
| 自选盘中行情 | AKShare 的股票 / ETF 行情或分钟接口；授权分钟源 | 交易时段60秒目标，先20—50标的 | 若接口只能全市场返回，只拉一次后过滤；批次超时不叠加 |
| ETF分钟归档 | `fund_etf_hist_min_em` | 闭合分钟增量，重叠回读最近5—10分钟 | 盘后重读可回补窗口；超出窗口标永久待补，不捏造分钟 |
| 股票分钟 | 授权后 `rt_min` / `stk_mins`；AKShare近期接口候选 | 自选优先，全市场分钟延后 | 分开核验历史 / 实时权限和频率参数 |
| 主数据 / 交易日历 / 复权 | Tushare对应端点或独立已验证来源 | 每日及变更时更新 | 没有确认日历时停止自动判定休市 / 数据缺口 |
| ETF NAV / IOPV / 份额 / 费率 | 基金披露或经过核验的基金接口 | 按实际披露频率；保留各自数据日 | 暂无可靠数据就显示缺失，不从价格推导净值 |
| 财报 / 行业 / 指数成分 | Tushare / AKShare / CNEquity候选 | 按公告与修订拉取 | 仅有“当前快照”的数据禁止伪装为历史成分 |

上述时刻和标的规模是首期设计值，不是上游承诺。股票接口见 [AKShare 行情文档](https://akshare.akfamily.xyz/data/stock/stock_quote.html)，ETF 见[基金文档](https://akshare.akfamily.xyz/data/fund/fund_public.html)，Tushare权限见[分钟文档](https://tushare.pro/document/2?doc_id=374)。

## 时效、错误与补数

- 分开记录 `event_time`（行情时点）、`source_published_at`（可空）、`fetched_at`（拉取时点）、`available_at`（本系统可用时点）。源没有时间戳时不伪造 event_time，质量状态为 `unknown_time`。
- 显示延迟依据行情时点，不依据“请求刚刚成功”。可配置目标：连续交易时段 event_time 落后超过120秒标 stale；没有时点标 unknown；午休 / 休市 / 停牌有独立状态。
- 单源并发起步1—2，调用预算按上游要求；指数退避加抖动，尊重 Retry-After。禁止多进程绕过限流。连续失败后断路，保留最后成功值并标 stale/error。
- 相同底层源共享限速器和故障状态；AKShare→efinance 若仍是东财，只是换适配器，不是恢复了独立数据源。
- `cursor` 只在原始数据持久化、校验和标准层提交完成后推进。分页若命中返回上限，缩小时间窗口继续，不把部分结果当完整。
- 按证券、频率、交易日记录 coverage 与缺口，不能只看全表最大日期。每日回读最近5个交易日作为初始修订窗口；公司行为变化触发相关历史派生视图重算。
- 一分钟一条快照不能复原真实分钟 OHLC。快照只进 quotes 表，只有来源确实提供完整分钟 bar 才进入 bars 表。

## 存储与核心表

原始层保存不可变 JSON/CSV/Parquet 与批次 manifest（请求参数、抓取时间、版本、内容哈希）；标准层统一符号、单位、时区并保留来源；服务层生成可解释的指标与筛选视图。

| 表 | 粒度 / 关键字段 | 用途 |
|---|---|---|
| instruments / symbol_aliases | 内部 instrument_id、交易所、资产类别、代码有效期、上市/退市日 | 股票与指数相同代码不冲突；处理改名改代码 |
| trading_calendar / sessions | 交易所、交易日、会话区间、版本 | 处理节假日、集合竞价、午休、异常休市 |
| quotes | 标的 + 源 + event_time + 批次 | 最新价、累计量额、盘口；不混入分钟K线 |
| bars_versions | 标的 + 频率 + bar_end + 复权口径 + 源 + revision_id | OHLCV历史与修订；当前版本视图另行裁决 |
| adjustment_factors / corporate_actions | 标的、有效日、披露日、因子版本、源 | 原始行情与复权派生分离 |
| fundamentals_versions | 标的、报告期、报表范围、公告 / 可用时间、修订版本 | PIT财务分析；保留原版和重述版 |
| etf_metadata / etf_nav | 基金、净值日、公布时间、NAV类型、规模/费率有效期 | 对比同指数ETF；区分收盘NAV与盘中IOPV |
| memberships | 行业 / 指数、成员、valid_from/to、known_at、源 | 正确构造历史股票池 |
| quality_events / coverage | 数据集、标的、日期、规则、严重性、证据、处置状态 | 面向用户的数据质量中心 |
| ingestion_runs / watermarks | 批次、参数哈希、行数、状态、游标、版本 | 续跑、审计、诊断 |

Parquet 初始按数据集 / 频率 / 年月分区；不要每只证券每天一个小文件。原始批次可小，标准层定期合并。DuckDB 由单写入进程维护目录与派生结果；API 查询已发布的不可变快照。多人写入需求出现后再增加 PostgreSQL 管理元数据。

## 清洗规则和处置

| 规则 | 处置 | 为什么 |
|---|---|---|
| 证券代码保持字符串，映射交易所及资产类别 | 无映射进隔离区 | `000001`既可能是股票代码也可能是指数代码 |
| 单位按端点版本声明，金额统一CNY元、量统一股/份 | 未知单位阻止进入标准层 | Tushare daily 的手 / 千元不能直接与元 / 股混用；ETF单位另证实 |
| 时区显式，bar时间明确开始或结束语义 | 无法判断时隔离或降为快照 | 09:30标记未必是一根完整分钟K线 |
| 数值有限、非负量额、有效OHLC正数 | 无效进隔离区；原始层保留 | 空字符串、NaN、占位0不得变成可交易价 |
| low ≤ open/close ≤ high | 失败隔离 | 避免坏K线进入收益计算；源缺少open不能随便补造 |
| 重复自然键与同键冲突 | 完全重复去重；冲突保留版本并按明确优先级裁决 | 不依赖随机“保留最后一行” |
| 缺失交易日 / 分钟 | 结合上市日、停牌、交易时段分类 | 停牌不是抓取失败；交易缺口不应无条件向前填充 |
| 价格跳变 | 先检查公司行为、板块规则、状态，再标异常 | 不能用统一10%阈值删除真实涨跌行情 |
| 多源价量差异 | 同时间、同单位、同复权后比较 | 成交量差100倍常是单位问题；不跨源求平均掩盖差异 |
| 修订与复权变化 | 保存旧版、重建派生值、更新版本号 | 前复权序列会随新公司行为变化，不能仅追加最后一天 |
| 财报 / 成分 / 宏观时点 | 公告可用后才进入对应历史研究 | 报告期不等于市场当时已经知道 |

Tushare日线的单位与停牌行为依据[官方daily文档](https://tushare.pro/document/2?doc_id=27)。其余规则为本项目设计，必须编写跨分红、停牌、重复、源中断、修订和未知单位的边界测试。

## 指标口径

- 收益率：日线研究使用明确的复权或总收益口径；前复权价格显示与原始成交价格分别标注。收益 / 风险比较保留基准、日期区间、费用与年化因子。
- ETF折溢价：盘中仅在价格与合格IOPV时间足够接近时算 `price / iopv - 1`；收盘对同日NAV另算。把盘中价格除昨日NAV只能标为“相对上一净值”，不能称实时折溢价。跨境ETF更不能隐去估值时差。
- 跟踪误差：同一日期网格的基金净值收益减基准总收益后，取标准差再年化；跟踪差异另列，不混称。缺少基准或净值历史时不计算。
- 最大回撤：同一有效净值序列计算 `equity / running_max - 1`；缺失区间报告覆盖，不能填0收益。
- 份额变动可用于估计净申赎，但必须处理拆分等公司行为；成交额不是资金净流入。不同平台“主力资金”定义不同，保留来源，放在第二阶段。
- PIT：提供“按公开时点重建”与“按系统实际可用时点重放”两种模式，后者要求 available_at；只有公告日期无精确时刻时，采取保守的下一交易会话可用规则并标注假设。

## API契约草案

`GET /api/v1/watchlist/quotes`、`/instruments/{id}/bars`、`/etfs/compare`、`/quality/events`、`/datasets/coverage`。

响应携带 `data_mode`（live/delayed/historical/demo）、源、单位、交易状态、时间戳、质量标记、schema_version、revision与缺失原因。大表服务端排序分页；分钟监控可先用条件HTTP轮询，后续共享SSE连接。不得将demo作为live请求失败后的静默回退。

首期验收建议：同一批次重跑无重复；进程中断可续跑；未知单位与坏OHLC被隔离；过期行情前端可见；日线缺口被逐证券列出；公开时点之前查不到财务修订；分钟源停更时旧值不被标为实时。性能目标待真实样本基准测试后确定。
