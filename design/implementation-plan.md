# 实施清单

本轮已完成：范围确认、16项目元数据核查、官方接口文档研究、3项连接探测、架构/界面设计、规范化行情契约草案。

## 第一步：建立可验收的数据竖切面

范围：20—50个自选 A股 / ETF；日线从2020年起或上市日起；一分钟数据仅要求从系统启动后持续保存，旧历史按可用窗口回补。

1. 隔离 Python 项目环境并锁定依赖版本；将本轮探测中可用的接口封装为 Provider。
2. 保存不可变原始批次，建立证券主表、单位映射、日历、日线和分钟表。
3. 实现未知单位拒绝、OHLC检查、版本去重、交易时段缺口分类和时间戳新鲜度。
4. 单次命令支持增量、回补和质量报告；先手工运行，验收后接定时器。
5. 在包含分红、停牌和异常行的样本上证明重跑一致；源返回空数据时不得推进游标。

验收：每一个展示值可回溯到批次；中断续跑不丢记录；不存在用0填行情、将历史缺口伪造成平盘、把分钟快照误作OHLC等行为。

## 第二步：做真实数据前端

建立只读API → 自选表 → 详情图 → 数据质量页 → ETF同类比较。先接价格、成交额和真实更新时间，再接基金净值与费率。无法确认时间/口径的列保持缺失。

验收：前端筛选排序与后端查询一致；点击行同步详情；切换复权清楚显示口径；源故障仍显示上次值及过期标识；小屏可操作；图表和表格数值同源。

## 第三步：验证可复用历史层

在独立目录验证CNEquity，锁定版本，不直接替换生产目录。用10只证券做原始/派生逐项核对、修订重跑和PIT边界案例；验收成功后通过适配器读入。若原有适配器已经满足需求，可保留CNEquity作为对照工具。

## 第四步：研究与扩展

历史成分、财报PIT、收益和回撤、ETF跟踪误差；再考虑Qlib/全球数据Provider。仅当任务规模需要时引入Dagster，或多人协作时增加PostgreSQL。

## 仍需实测的事项

- 免费上游在完整交易日内的p50/p95延迟、失败率、批量耗时与限流行为。
- ETF各端点的成交量单位、IOPV质量、历史份额与费率覆盖。
- 退市证券历史、历史成分、复权因子和历史修订的完整性。
- 如接Tushare，具体账号所具备的股票/ETF分钟、基本面权限；本轮未使用账号或Token。

不把开源仓库维护活跃度、单次接口连通或漂亮界面当作以上验收的替代品。
